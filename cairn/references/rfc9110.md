# rfc9110: the URI length that HTTP senders and recipients are asked to support

**Provenance.** Ingested 2026-10-01 at M153 from `https://www.rfc-editor.org/rfc/rfc9110.txt`, the RFC Editor's plain-text copy. No file is on the shelf.
Pagination: none in this copy. The value is cited by section.
Extraction: the value below was copied from section 4.1 on 2026-10-01 (observed 2026-10-01). An RFC does not change after publication, so a re-check looks only for a later RFC that obsoletes RFC 9110.

**Citation.** Fielding, R., Nottingham, M., & Reschke, J. (Eds.) (2022). *HTTP Semantics* (RFC 9110, STD 97). Internet Engineering Task Force. https://www.rfc-editor.org/rfc/rfc9110

**Role.** hitop-form's Study Link Builder shows a warning for a study link longer than 8,000 characters. This page records the standard behind that number.

## Extracted values

- Section 4.1, "URI References": it is RECOMMENDED that all senders and recipients support URIs of at least 8000 octets in protocol elements.
- The same paragraph notes that some structures, such as the HTTP/1.1 request line, will then be larger.
- The RFC states a minimum to support. It sets no maximum, and it does not say which software supports less.
