## Candidates

- A module descriptor records the scales but not the column names the export will produce (`HSR_007` from Qualtrics, `hsr_007` from REDCap), so `score_hitopsr()` still needs `items` typed out — `names(collected)` in the easy case, a hand-written selection where the collected frame carries other columns too. Adding a `columns` field and a helper that resolves it against the data, erroring loudly on any mismatch, is the shape considered; declined at the 2026-08-24 M054 plan gate because those names exist only once a generator has run, which puts the field with M055's sidecar rather than with the format, and because matching columns silently is the failure GP2's warnings exist to prevent. Distinct from the standing M037 row below, which is the no-descriptor case. Promote if a researcher reports the descriptor still leaves the tedious half of the typing, or when M055 lands — added 2026-08-24 — lineage: M054 (plan gate, out of scope)

- The builder app exposes fewer generator arguments than the package does, in three families triaged down at three gates. Word typography and header: none of `generate_docx_hitopsr()`'s `title`, `font_size`, or `font_family`, so every Word download carries the default header at 10pt Times New Roman — typography and a label, not instrument content, and `title` sits under IP1 as participant-facing text (D-037). Online exports: neither `include_instructions` (Qualtrics) nor `breaks` (both), so every online download carries the administration instructions and paginates every 15 items — `include_instructions = FALSE` drops participant-facing content, IP1's scope, needing sign-off before a public control, while `breaks` is pagination only; M050 guards both package-side without exposing either. Scoring key: no `include_scoring` control, so the Word download always carries the scoring-key page a package caller can turn off — not a hazard the app introduced, the shipped `inst/extdata/hitopsr_A4.docx` carrying the same key. Promote per family: a study-specific header or a larger print form; an unpaginated or instruction-free online export; a participant-facing form without the key — added 2026-08-22, merged 2026-08-24 — lineage: M045 (review finding 4), M049/M050 (plan gates, out of scope)
- Neither `generate_qualtrics_hitopsr()` nor `generate_redcap_hitopsr()` checks that `id_prefix`, `block_name`, or `form_name` is a name its target system accepts — a space in `id_prefix` or a capital in `form_name` yields a dictionary REDCap or Qualtrics rejects at import, with nothing said at generation. M050 adds type and shape guards but not format rules: no citable REDCap or Qualtrics naming spec sits on the `references/` shelf, and IP2 bars inventing one. Promote once such a spec is ingested, or if a user reports an import rejected on a name the package accepted — added 2026-08-23 — lineage: M050 (plan gate, out of scope)
- The five `*_qualtrics.txt` byte-locked artifacts in each of `inst/extdata/` and `pkgdown/assets/downloads/` are protected only by their directory's `-text` rule: carrying neither a NUL byte nor a CR, they are invisible to M047's line-ending guard and git's content sniff reads them as text — the pairing that let a Windows checkout mutate them at M020. `*.qsf` gained an extension rule at M047; `.txt` did not, since a blanket `*.txt -text` would freeze every ordinary text file. A path-scoped rule, or a guard clause keyed to the manifest, would close it; the md5 lock still catches an actual byte change, so this is guard reach, not a live defect. Promote if an artifact `.txt` is moved or added outside those two directories, or if the md5 lock trips again on a line-ending conversion — added 2026-08-22 — lineage: M047 (review finding 10, partially addressed)
- The browser module builder ([jmgirard/hitop-builder](https://github.com/jmgirard/hitop-builder)) installs whatever `hitop` r-universe currently serves, with no version pin, no CI, no smoke test and no timeout on a stalled install — so a pre-CRAN API change (the kind M043 made to `subset`→`module`) silently breaks the deployed page for the next visitor, undetected in either repo, and its README's named version drifts. Version pin versus release-checklist entry is the open question. Promote when a `hitop` release changes any surface the app calls (`available_scales()`'s three columns, `hitop_module()`'s camelCase stems, the generators' `file`/`module`/`papersize` arguments), or if a visitor reports the page failing — added 2026-08-22 — lineage: M045 (review findings 1, 2, 6, 12)
