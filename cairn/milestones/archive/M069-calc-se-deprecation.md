# M069: `calc_se` is deprecated in favour of the interval functions

**Status:** done (2026-08-30, PR #75 https://github.com/jmgirard/hitop/pull/75)

**Goal:** Calling any `score_*()` function with `calc_se = TRUE` warns that the argument is deprecated and points at the interval functions, while returning exactly what it returns today.

**Outcome:** `deprecate_calc_se()` sits beside `deprecate_subset()` in `R/util.R` and fires from `score_engine()` inside the `calc_se` block, after every validation, so a call aborting on its data, items or an append collision reports that alone. `call` is threaded so `conditionCall()` names the wrapper, and a `se_instead` string threaded from each wrapper carries a per-instrument replacement: `interval_hitopsr()`, `interval_hitopbr()`, and for the PID-5 "no interval function; see `reliability_pid5()`". The warning class `hitop_deprecated_calc_se` is a public contract, named on all three help pages and in NEWS. `data-raw/characterize_calc_se.R` is the D-011 harness: 48 configurations across the three functions, every `missing`/`append` combination, six shipped datasets, and `score_hitopsr()` both with and without a module — all 48 `identical()` in value and condition classes against the branch point. Nothing scored moved. Help pages and four vignettes now describe the number, say it is deprecated, and name the replacement; the HiTOP-SR and HiTOP-BR vignettes hand their demonstration to their existing interval sections, while the PID-5 short-form vignette and the `score_pid5()` example keep their calls, having no replacement to switch to. `tests/testthat/helper-fixtures.R` gains a class-targeted `hush_se()` wrapping 23 pre-existing call sites so the deprecation does not bury the suite's warning channel, and `test-vignette-se-prose.R` now discovers its file set by scanning `vignettes/` rather than listing it.

**Decisions:** D-049 records the deprecation, the public condition class, the per-instrument routing, and the rejected shared-message and remove-outright alternatives. DESIGN Known issue #4 is corrected in place: the `_se`-where-`NA` masking inconsistency is carried to the removal rather than repaired, reopening if the removal candidate is dropped. `PROFILE.md`'s deprecation-mechanics line now names the hand-rolled classed warning this repo uses instead of `lifecycle::deprecate_warn()`.

**Review:** Three fresh-context reviewers on distinct evidence; the prior-review lens found no prior-review evidence bearing on the diff. Twelve findings, none meeting the return floor. Ten fixed at the gate — chief among them a botched ROADMAP compression that deleted the maintainer-run verification-tooling candidate row and left a duplicate of the browser-builder row in its place, and a NEWS sentence claiming no `_se` value changed while the same unreleased section's HiTOP-BR rekey moves two. Also fixed: the public condition class named on no help page, a `DESIGN.md` won't-fix stated harder than the decision behind it, three vignette prose seams, an unannotated deprecated example, in-loop assertions with no failure label, and a miscounted comment. Two filed to the M068 test-reach candidate row: the harness's condition-channel comparison is inert on its own matrix, and the warnings-before-abort sweep does not yet cover the three `score_*()` functions. Jeff accepted `ROADMAP.md` sitting over its byte budget rather than drop those two filings.
