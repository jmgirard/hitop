# M121: `read_form_responses()` and hitop-form refuse a malformed file by name: a short or long row, an empty file, a value refusal naming no row, an unnumbered or second-stem item column, and a descriptor whose items are not ascending

**Status:** done (2026-09-24, PR #132 https://github.com/jmgirard/hitop/pull/132; hitop-form PR #9 https://github.com/jmgirard/hitop-form/pull/9, open at archive time for Jeff to merge from his terminal, the deployed-page dispatch after it)

**Goal:** A malformed hitop-form file stops at `read_form_responses()` or at the hitop-form page with a message that names the file, the row or column at fault, and the fault, instead of reading as data or as an unrelated fault.

**Outcome:** In hitop, `read_form_response_file()` gains four unclassed refusals naming the file (D-064's terms). `count_form_fields()` counts each line's fields over a `UTF-8-BOM` connection with `utils::count.fields()` (`sep = ","`, `quote = "\""`, `comment.char = ""`) before `read.csv()`; `NA` counts (a quoted line break's continuation lines) fold away; no record at all is "no header row" (zero bytes, blank lines only, a BOM only), and a record whose count differs from the header's is refused with one line per row ("Response row r holds n fields, and the header holds h"). After `item_cols`, a name outside `item_column_pattern` (`^[a-z0-9]+_[0-9]+$`) is refused naming the columns, and more than one stem (the name before `_[0-9]+$`) is refused naming the stems, both before the value checks. The whole-number, integer-range, `form_build` and `submitted` refusals carry "Response row(s) …", counted from the first row after the header. No `rlang::try_fetch()` around `read.csv()` (the plan's text): the count runs first, so its empty-input error is never reached. Docs: `?read_form_responses` Details, `?write_module`'s `items` text (the page requires ascending, `read_module()` compares as a set), the online-collection article's two-forms paragraph (two stems refused; one stem reads as one frame, unless a module's random-order rows carry an `item_order` of the module's items only), NEWS. Tests: 21 refusal tests plus the `#` cell and quoted line-break reads. In hitop-form, `checkModule()` refuses `items` with any entry below the one before it, after the repeat check and before the `itemOrder` check, with "its items are not in ascending order."; helpers `NOT_ASCENDING`, `NOT_ASCENDING_MESSAGE`, `notAscendingDescriptor()`; G13 and L15 over `module-plain.json` reversed and with its last two swapped; README step 4, the file paragraph and the two test rows. Playwright 201 tests.

**Decisions:** none milestone-local. D-073 (promoted at plan) governs the page's ascending-items check and `read_module()`'s unchanged set comparison.
