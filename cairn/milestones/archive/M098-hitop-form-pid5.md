# M098: hitop-form renders the three PID-5 forms from the package's JSON exports

**Status:** done (2026-09-21, PR #107 https://github.com/jmgirard/hitop/pull/107; code in hitop-form PR #1 https://github.com/jmgirard/hitop-form/pull/1, merged as bfb1d9c).

**Goal:** Extend `jmgirard/hitop-form` so a study link naming `pid5`, `pid5sf` or `pid5bf` renders that PID-5 form from the package's export and saves the same response file it saves for the HiTOP forms.

**Outcome:** In hitop-form, `INSTRUMENTS` in `form.js` gained `pid5: 'PID-5'`, `pid5sf: 'PID-5-SF'` and `pid5bf: 'PID-5-BF'`, and the `link.html` selector gained `PID-5 (220 items)`, `PID-5-SF (100 items)` and `PID-5-BF (25 items)`. The module hint already read "Optional, HiTOP-SR only." and is unchanged. The page renders the exports' text and 0-to-3 options unchanged and saves the same CSV, with each answer written as the option's value. Tests: a new `tests/link.spec.js` (7 tests: the selector, a built link per form, the module hint). The render spec runs over five forms and checks the heading, item count and option values against stated values and the export. Three PID-5 save cases include S7, a chosen 0 written as `0`. Three fixtures, `responses-pid5.csv`, `responses-pid5sf.csv` and `responses-pid5bf.csv`, were captured with `WRITE_FIXTURES=1 ... -g pid5`. The fixture note names `read_form_responses()` and says the package has no PID-5 reader tests yet. The README names the five forms, the PID-5 item names and 0-to-3 values, and `read_form_responses()` plus `score_pid5(..., version = "BF")` for scoring. The suite went from 22 to 35 tests. The hitop repo changed only `cairn/`.
