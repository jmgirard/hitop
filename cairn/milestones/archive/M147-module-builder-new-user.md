# M147: Module Builder: short start, labelled picker, clear hand-off

**Status:** done (2026-09-30, PR #155 https://github.com/jmgirard/hitop/pull/155; companions hitop-builder PR #24 https://github.com/jmgirard/hitop-builder/pull/24 and hitop-form PR #20 https://github.com/jmgirard/hitop-form/pull/20)

**Goal:** A researcher who opens the Module Builder for the first time reads a short start and understands the scale list. The download button sits beside the format cards, and one step leads to the Study Link Builder.

**Outcome:** In hitop-builder `index.html`, the text from the `<h1>` to the status line is 49 words. The host list, the version line and the R log sit in a closed "Technical details" section. `showFailure()` opens it on a load or build failure and names it in the status. Each scale row has its item count ("<n> items") in the checkbox name and a "Definition" button in place of the hover popup. An empty filter shows "No scales match the filter." in a status region. Step 2 holds at most 60 words per format. The heading ring moved from `:focus` to `:focus-visible`. Each format has one name in `FORMATS[].label` ("Word form", "Qualtrics file", "REDCap dictionary", "Online form"). Its card, button, `buildStatus()` and README.txt title use it. The step controls name their target step. After an Online form save, `showNextStep()` puts in a "Next: make the study link" panel. Its link opens the Study Link Builder in a new tab. `removeNextStep()` takes it out on a selection or format change. README.md opens with "Using the page" and ends with "For developers". Smoke steps A20 to A30 were added, with plants aa to at (47 in all). `tests/prose.mjs` checks D-083's retired names and exits 1 on a body text node in no passage or an empty body. In hitop-form `link.html`, "Choose the module file" fills the module box from a file. `tests/link-module-file.spec.js` (MF1 to MF5) covers it. In hitop, NEWS has the entry and two articles name the file choice.

**Decisions:** M147-D1 set the four format names, the step names and the button labels. It also chose a Definition button that shows the definition under the row, and a hand-off in a new tab. M147-D2 keeps the note that the format cards are off during a build in README.md only. It replaces M104's choice to say it on the page too.

**Review:** Four passes with the three-lens fan-out, two defect returns and one amendment return. Pass 1 found no build-failure smoke step (AC1), and a count check on 2 rows with the button driven on the first row only (AC2). It also found anchor-only panel counts (AC5) and no NEWS entry. AC2 was narrowed at the gate. Pass 2 found that `prose.mjs --text` dropped text after inline elements (AC6). Pass 3 found that AC6's "every string a visitor can read" failed on the package's scale text and two pinned "Ready." statuses. `prose.mjs` excludes both on purpose since 2026-09-11. AC6 was narrowed to what `--text` writes, after two re-audits. Pass 4 met all seven criteria. Its gate fixed eight findings. Among them were stale naming sentences, the lede's pointer to "Technical details" and an empty-body floor in the prose check. At hygiene the "Module Builder test reach" row was promoted to plan next with M147's test follow-ups. The file-read follow-ups joined the Study Link Builder row. The Chromium-only focus ring became Known issue 14, and the M141 row was pruned.
