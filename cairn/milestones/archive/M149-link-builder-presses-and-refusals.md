# M149: Study Link Builder: early presses, file reads and refusals

**Status:** done (2026-10-01, PR #156 https://github.com/jmgirard/hitop/pull/156; companion hitop-form PR #21 https://github.com/jmgirard/hitop-form/pull/21)

**Goal:** On the Study Link Builder, an early press, an edit during a file read and a refused field each end as the researcher expects.

**Outcome:** In hitop-form `link.html`, "Make the link" has `disabled autocomplete="off"` in the markup. The script enables it after the prefill's `try`/`catch`, just before it adds the submit handler. The module box's `input` listener adds 1 to `moduleReads`, so a typed edit wins over a file read still running. `labelText()` reads the label's child nodes in place, with no `cloneNode`. `showKind()`, `showSite()`, `showHeld()` and the section-open loop run inside the prefill's `try`. Its `catch` hides the site hints and destination blocks, removes the menu's `aria-describedby`, sets every summary to "Not used" and closes every section. `QUESTION_CONTROLS` holds name, text, options, min and max, with no `qList` fallback. An instruments refusal focuses `rows[e.index]`. The `nextStep()` local is `runSql`. In `form.js`, `checkInstruments` puts `index` on its error for an unknown entry, the later of a repeat and the second PID-5 form. `parseLink()` refuses a present `instrument` that is not a string before any export request. The export refusal in `checkModule` says "Use", not "Paste". Tests: L34 in `link.spec.js`, MF6 and MF7 in `link-module-file.spec.js`, I3 in `instruments.spec.js`, and S10, S11 and S12 in `link-sections.spec.js`. S12 fires each of the 23 `refuseAt()` calls, 36 cases, and checks focus. In hitop, NEWS.md has the entry.

**Decisions:** The plan chose a button disabled in the markup over an early script that cancels submits. `checkInstruments` keeps `bad(why)` and adds `index` to the error. The question refusal maps only the five fields the editor can fault, and any other fault focuses the message.
