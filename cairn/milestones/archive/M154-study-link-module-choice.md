# M154: "HiTOP-SR module" as an instrument choice

**Status:** done (2026-10-02, PR #163 https://github.com/jmgirard/hitop/pull/163; companions hitop-form PR #27 https://github.com/jmgirard/hitop-form/pull/27 and hitop-builder PR #25 https://github.com/jmgirard/hitop-builder/pull/25)

**Goal:** A researcher who wants a HiTOP-SR module chooses "HiTOP-SR module" in the instrument list and gives its module file in that row.

**Outcome:** In hitop-form `link.html`, `OFFERED` gains `hitopsr-module` ("HiTOP-SR module (scales you choose)") after the HiTOP-SR, and `stemOf()` maps it to `hitopsr`. `addModuleFields()` gives each row its own "Module file" box, file control, alert and status, shown only in a module row. Each row has its own numbered reads and an `isConnected` check. The optional section is now "Item order", with only the shuffle box. A module row writes the same link as before. The repeat refusal covers a HiTOP-SR row beside a module row and two module rows, and an empty module box is refused at its box. `fill()` makes a module row from a `c`, `z` or setup link with a `module`. It refuses a module with no HiTOP-SR, and checks `instrument` against `INSTRUMENTS`, so the menu value never opens. "Add an instrument" skips both HiTOP-SR entries. Tests include LI6 to LI9, MF8 and the LI7 oracle from `main` at `2af14f0`. The review added to LF7 and BAD_C, for 1001 tests. hitop-form and hitop-builder READMEs, both hitop articles, NEWS and DESIGN Known issue 11 name the new row.
