# M106: Keyboard focus comes back when a builder build ends

**Status:** done (2026-09-22, PR #116 https://github.com/jmgirard/hitop/pull/116; code in jmgirard/hitop-builder PR #21 https://github.com/jmgirard/hitop-builder/pull/21, merged 2026-09-22T20:31:46Z)

**Goal:** When a builder build ends, keyboard focus is back on the control that had it at the build click.

**Outcome:** In hitop-builder `index.html`, `download()` keeps `document.activeElement` as `focusAtClick` before the button and cards go off. In `finally`, after `refreshTally()`, it calls `focus({ preventScroll: true })` on that element only if focus is on the body, and the element is connected, not disabled and has client rects. So focus returns after a save and after a failure with no scroll. Focus on another element stays there, and an off or hidden control gets none. Two comments say why and name Safari and Firefox as unchecked. README.md step 2 states the rule without listing click cases. `tests/smoke.spec.js` adds A11, which blurs the step heading the smoke build leaves focused and then polls for `#downloadBtn` after the save. `tests/plants.mjs` adds plant (l), which removes the `focus()` call and fails A11 alone. This repo: tracking only, plus one candidate row.

**Decisions:** none cross-cutting. Plan gate: return focus only to a control that is on and shown, and only without scroll. Guard with a smoke assertion plus a plant. After return 2, the README states the code's rule and lists no click cases (thrash trigger (b), chosen over a `/milestone-brief` escalation).

**Review:** three passes, two defect returns, both on AC6. Each time a README sentence listed focus cases from recall. First "it stays where you put it" (a click on the log drops focus to the body, and focus comes back). Then "text other than a step heading takes no focus" (a click on a `<summary>` takes focus). Pass 3: AC1 to AC5 by held-worker probes on the branch page, a `stop()` copy, main's page and a plain-`focus()` copy (`scrollY` 1248 kept against 899). AC6 by the grep read. AC7 by local smoke, 12 plants red, and PR #21 smoke green. `check()` 0/0/0, and PR #116 8/8 green. Three-lens fan-out: no behavior bug. Fixed before merge: the comments now name the kept element and both browsers. "still" and "the control from your press" were reworded, and a smoke comment plural was fixed. Follow-up: the focus-return coverage candidate row (test gaps, the A11 false-red window, the live-region overlap, Chromium-only checks). Rejected: the `visibility: hidden` edge (no control in that state) and a line outside the diff. A focus-ring worry was checked: `:focus-visible` is true after a keyboard build in Chromium. No lesson added. The derived-claims rule already covers prose from recall. Nothing retired.
