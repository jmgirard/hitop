# M110: Scoring refuses SPSS missing codes and 64-bit integers it misreads

**Status:** done (2026-09-23, PR #121 https://github.com/jmgirard/hitop/pull/121)

**Goal:** The scoring functions abort and name an item column that holds SPSS user-missing codes or 64-bit integers, instead of scoring wrong numbers in silence.

**Outcome:** `unparsed_value()` in `R/util.R` now returns a reason with a kind: `text`, `missing`, `integer64` or `type`. An `integer64` column is refused before the numeric acceptance. A `haven_labelled_spss` column that holds a value its `na_values` or `na_range` declares missing is refused, and `declared_missing()` reads those attributes without calling haven. The message shows the first such value and names `haven::zap_missing()`. `item_values()` unclasses haven labelled columns, and `item_numbers()` replaces `as.numeric()` in `prep_items()` and `validity_pid5()`, so labelled digit text scores. `is_invisible()` and `code_points()` show a refused value made only of `\p{Z}`, `\p{Cc}` and `\p{Cf}` characters by its code points. The same applies to a declared-missing code. Each refusal shows only its own tips: choice text, `as.numeric()` after `library(bit64)`, or `haven::zap_missing()`. The seven functions of D-068(a) are covered. The `items` docs and the M109 NEWS entry are updated.

**Decisions:** D-069. An amendment gate replaced AC5's `[[:graph:]]` predicate with Unicode categories, because TRE and PCRE place U+00A0, U+FEFF and U+200B differently.
