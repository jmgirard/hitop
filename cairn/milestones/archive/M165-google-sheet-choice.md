# M165: Google Sheet choice in the Study Link Builder

**Status:** done (2026-10-06, PR #173 https://github.com/jmgirard/hitop/pull/173; companion hitop-form PR #30 https://github.com/jmgirard/hitop-form/pull/30)

**Goal:** The Study Link Builder offers "A Google Sheet" as a destination, with its setup steps and script on the same page.

**Outcome:** In hitop-form `link.html`, "Where responses go" has four choices. "A Google Sheet" (value `sheet`) and "Another web address" (value `webhook`) sit between the file and the Supabase table. Both web choices write `store: {kind: 'webhook', url}`, so the link format and `form.js` are unchanged. `#sheetFields` holds four setup steps (`ol#sheetSteps`), a "Copy the script" button and a "Web app URL" field (`sheetUrl`). The button copies a `<script type="text/plain" id="sheetScript">` copy of the README's Apps Script, and it is hidden where the browser has no clipboard. `isSheetUrl()` accepts https, host `script.google.com`, the default port and a path ending in `/exec`. `readForm()` runs it after `checkStore()` and refuses other addresses at the field. The prefill of a `c`, `z` or setup-file link picks the choice from the address, and the notice labels it "Web app URL" or "Web address". `#destHint` names "A Google Sheet". New `tests/link-sheet.spec.js` (G1 to G5) compares the copied script with the README block. Older link, section and consent tests cover the new choice. The hitop-form README, `online-collection.Rmd`, `pid5_scoring.Rmd`, `modules-hitopsr.Rmd` and NEWS name the choice.

**Decisions:** none promoted. Jeff chose a separate choice over a renamed one, steps and a copy button over a README link, and a refusal over a warning. The plan kept the link format rather than adding a store kind.
