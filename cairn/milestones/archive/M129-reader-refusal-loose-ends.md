# M129: `read_form_responses()` caps its line and row refusals at five, refuses a UTF-16 file once, and keeps the mismatch class when a path holds a brace

**Status:** done (2026-09-27, PR #140 https://github.com/jmgirard/hitop/pull/140, merged 2026-09-27T21:11:09Z)

**Goal:** A malformed or mis-encoded hitop-form file stops `read_form_responses()` with a message of bounded length that names only lines the file holds, and a differing file's path never breaks the mismatch refusal.

**Outcome:** Closes M123 review F2, F4 and F6. A new helper, `form_first_five(lines, noun, total)`, shows the first five bullets and then "... and n more lines/rows/cells.". It serves the byte (NUL or non-UTF-8), whitespace-line, field-count, `instrument`-cell and item-value refusals. The date and `item_order` row lists stay inline (Out scope). `form_is_utf16()` runs first in `form_file_lines()`. It flags a file that starts with FF FE or FE FF. It also flags a first line of at least 2 bytes with a NUL at every even or every odd offset. Such a file is refused once, naming the file and no line, and asking that it be saved as UTF-8. The mismatch bullets go through `form_bullets()`, so `b{x}.csv`, `b{.csv` and `b{.val x}.csv` keep `hitop_form_responses_mismatch` and show as written. Details and NEWS describe all three. Tests: 17 cap tests, 12 UTF-16 refusals, 4 UTF-8 controls, 5 brace-path tests.

**Decisions:** none cross-cutting. The plan gate capped the field-count refusal, reversing M121 review F3, because each shown row keeps its own count. It chose one whole-file UTF-16 refusal over correcting UTF-16LE line numbers.

**Review:** two passes. Pass 1: AC4 failed as written. It asked Details to say "the line and row errors" cap at five, which is false for the date and `item_order` errors. Amendment return 1 reworded AC4 to the four capped errors, and two fresh readers cleared the text. Pass 2: all five criteria pass. Suite 0 failed of 20755, check 0/0/0, PR CI 8 of 8.
