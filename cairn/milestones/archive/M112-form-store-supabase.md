# M112: hitop-form inserts each participant's responses into a Supabase table named in the study link

**Status:** done (2026-09-23, PR #123 https://github.com/jmgirard/hitop/pull/123; code in hitop-form PR #3 https://github.com/jmgirard/hitop-form/pull/3, merged as c15e149).

**Goal:** Add a second store kind to `jmgirard/hitop-form`, `supabase`, that inserts the finished responses as one row of a table the researcher owns, with the link builder writing the SQL that creates that table for the chosen form.

**Outcome:** In hitop-form, a study link's `store` may be `{ kind: "supabase", url, key, table }`. `checkStore()` keeps only the project origin (a pasted `/rest/v1` suffix and trailing slashes dropped; any other path, query or fragment refused), accepts a publishable or anon key only (a `sb_secret_` key, a JWT whose `role` is not `anon`, a key with a space or non-ASCII character refused), and holds `table` to `TABLE_NAME` (`^[a-z_][a-z0-9_]{0,62}$`). At Finish, `sendRequest()` posts M111's JSON row to `<origin>/rest/v1/<table>` with `apikey`, `Content-Type: application/json`, `Prefer: return=minimal`, and `Authorization: Bearer` only for a JWT-shaped key; a 2xx confirms, a redirect (`redirect: 'manual'`) does not. link.html gained a "Send responses to" kind selector (file, web address, Supabase table), the three Supabase fields, and `storeSql()`: five text columns, one integer column per item in shown order, RLS on, default grants revoked from `anon` and `authenticated`, insert granted to `anon`, one insert policy; the button is disabled during the export fetch.
