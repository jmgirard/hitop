# M142: HiTOP-SR module functions refuse a module whose items do not match its scales

**Status:** done (2026-09-29, PR #153 https://github.com/jmgirard/hitop/pull/153)

**Goal:** Every HiTOP-SR function that takes a module accepts only a module whose items are the items its scales cover. That guarantee lets `generate_docx_hitopsr()` add the module's own subscales to its scoring page.

**Outcome:** `check_module_build()` in `R/module.R` rebuilds a module with `hitop_module()` from its `instrument` and `scales`. It compares `items`, `nItems`, `camelCase` and `instrument`, and refuses under the public class `hitop_module_mismatch`. It also refuses an object that is not a list and a module that cannot be rebuilt, with the `hitop_module()` error as parent. `write_module()`, `score_hitopsr()`, `reliability_hitopsr()` and the three HiTOP-SR generators run it before any file opens. The message names every lacking, extra and repeated item through `item_ranges()`, which prints runs of whole numbers as "a-b" with no cut. The unclassed `nItems`-consistency refusal of `module_engine_inputs()` is gone. `module_subscales()` picks the subscales of held parents for scoring and the Word form, and holds the subscale-item abort. `generate_docx_hitopsr()` drops its refusal of `module` with `include_subscales = TRUE` and adds the in-module subscale rows. It checks the flag with `validate_flag()`. NEWS carries two Breaking entries and one New features entry. New test file `test-module-mismatch.R`.

**Decisions:** M142-D1: the check also compares `instrument`, which widens D-081(a)'s field list by one field. D-081's Consequences name the abort in `add_hitopsr_subscales()`, and it now lives in `module_subscales()`. The branch reverses M024's milestone-local refusal of `include_subscales` with a module (M141 plan gate, D-081 Context).
