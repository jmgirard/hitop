# M116: A study link can ask hitop-form to show each participant the items in a fresh random order

**Status:** done (2026-09-23, PR #127 https://github.com/jmgirard/hitop/pull/127; hitop-form PR #5 https://github.com/jmgirard/hitop-form/pull/5)

**Goal:** A link field `shuffle: true` makes hitop-form draw a new random order of the planned items on each load. The row and the file keep the item columns in the instrument's order under the official item names and record the shown order in an `item_order` column.

**Outcome:** In hitop-form: `parseLink()` reads `shuffle` and refuses a value outside `true` and `false` by name. `planItems(exp, module, shuffle)` returns `{ items, shown }`. `shuffleItems()` is a Fisher-Yates over `crypto.getRandomValues` with rejection at or above the largest multiple of the range. Under shuffle the columns keep the export's order (a module's `items`, its `itemOrder` not followed). `buildCsv()` and `buildRow()` write `item_order` sixth, and `storeSql(table, items, shuffle)` adds `"item_order" text` after `submitted`. `link.html` has the "Show the items in a random order" box and its hint. Tests: render R7 to R9, refusals G9, saves S8 to S10, sends T12, SQL L7 against two fixtures, the box L9. The deployed-page run was dispatched after the merge. In hitop: `?read_form_responses`, the online-collection and modules articles and the PID-5 vignette describe the column, with a NEWS entry. `responses-hitopbr-shuffled.csv` ships with a provenance row and a test that scores it through `score_hitopbr()` against means recomputed from the package tables.

**Decisions:** none. D-070 governs, and the IP1 sign-off on display order was recorded at the plan gate.
