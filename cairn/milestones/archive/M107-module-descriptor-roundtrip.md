# M107: A module descriptor reads back as the format documents it

**Status:** done (2026-09-22, PR #117 https://github.com/jmgirard/hitop/pull/117)

**Goal:** A module descriptor that `write_module()` writes reads back through `read_module()` as the format documents it, on every platform.

**Outcome:** `write_module_impl()` writes through `file(open = "wb")` with `enc2utf8()` and `useBytes = TRUE`, so every platform writes LF with no CR. Before it opens the path, it rebuilds the module with `hitop_module()` from `instrument` and `scales`. It refuses `items` that are not numeric or differ in value or order, and an `nItems` that differs, with a {cli} error that names the field. A failed rebuild aborts with the rebuild's error as parent. The path stays as it was, and the file holds the rebuild's fields. `read_module()` reads `items`, `nItems` and `itemOrder` from a second `simplifyVector = FALSE` parse. `read_module_numbers()` accepts only whole finite JSON numbers, so strings, booleans, `null` elements and fractions are refused. The message names the shape per field. `?write_module` and `?read_module` state that a `hitop_subset` or a double-items module reads back as a `hitop_module` with integer items. NEWS has two Breaking changes entries and one fix entry. Absorbed the M086 CRLF row and the three M054 descriptor gaps. The column-names remainder stays a candidate.
