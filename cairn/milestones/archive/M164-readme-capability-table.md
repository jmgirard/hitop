# M164: README capability table

**Status:** done (2026-10-04, PR #172 https://github.com/jmgirard/hitop/pull/172)

**Goal:** Replace the README's "Development Progress" checklist with a table of what the package does for each instrument, kept true by a test.

**Outcome:** README.Rmd lost its checklist. It now has a `## What the package covers` section with one table of 11 instrument rows. The columns are Instrument, Items, Scoring, Reliability, Tutorial (links to the site's scoring articles) and Forms (Word, Qualtrics, REDCap, JSON). A sentence below the table points to `?validity_pid5` and `?norm_pid5`. Key Features has 3 plain bullets that name no instrument. The instrument full names and the child age range moved to the new section. `tests/testthat/test-readme-capabilities.R` parses the table and checks each cell in both directions against the package. It reads the item tables, top-level vignettes and `hitop_artifacts` formats, and calls each exported `score_*()`/`reliability_*()` function on one row with no warning. Tutorial links must be the full article URL. A coverage case fails when an artifact instrument, an exported scoring stem or a `score_pid5()` version has no row. Under R CMD check, where README.Rmd is build-ignored, the test skips. CLAUDE.md's keep-in-step rule names the table. The PID-5-FFBF Forms cell is blank until M163's artifacts land, and the test then fails until that branch fills it.

**Decisions:** none promoted. At the plan gate Jeff chose the capability table over a links section and asked for Key Features to be tidied too. Validity and Norms columns were dropped, because the child and forensic rows need judgments the column rules cannot state. No NEWS entry, because the README is not package behavior.
