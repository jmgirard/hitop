# M099: The package's reader scores the three PID-5 forms saved by hitop-form

**Status:** done (2026-09-21, PR #108 https://github.com/jmgirard/hitop/pull/108).

**Goal:** Prove that a PID-5 file saved by hitop-form round-trips through `read_form_responses()` and `score_pid5()` for each of the three versions. Document the hand-off in the PID-5 vignettes.

**Outcome:** Three fixtures, `responses-pid5.csv`, `responses-pid5sf.csv` and `responses-pid5bf.csv`, were copied from hitop-form `bfb1d9c` as LF. Their provenance row is in `tests/testthat/fixtures/README.md`. `test-read_form_responses.R` gained one test per version. Each test checks one row, the named integer item columns, every file value against the read data, and every `0` read as `0L`. It also compares `score_pid5()` with means recomputed from the file text. The recomputation uses `table_means()`, `pid_items$Reverse`, `pid_scales` and `pid_domains`. `pid5_scoring.Rmd` gained "Collecting Responses Online with hitop-form", and the SF and BF vignettes point to it in one sentence each. The `?read_form_responses` help page now names the PID-5 columns and links `score_pid5()` and `vignette("pid5_scoring")`. NEWS extends the `read_form_responses()` entry. The function code is unchanged.

**Decisions:** none cross-cutting. The plan gate chose one vignette section with two pointers over three copies or a shared article.
