# M097: The package ships JSON exports of the three PID-5 forms as checksum-locked artifacts

**Status:** done (2026-09-20, PR #106 https://github.com/jmgirard/hitop/pull/106).

**Goal:** Ship one format-1.0 JSON file per PID-5 form (FULL, SF, BF) that holds its items, response options and administration instructions as the package's tables hold them. Each file is locked to the tables by test and to the manifest by checksum, so hitop-form can render the PID-5.

**Outcome:** `write_instrument_json()` in `data-raw/json_export.R` gained version subsetting. It keeps the rows whose `number_col` is not `NA`, ordered by that column. The `FULL`, `SF` and `BF` columns of `pid_items` thus yield three files. The step changes nothing on the two one-form HiTOP tables, which rebuilt byte-identical. Three specs were added: `PID-5`, `PID-5-SF` and `PID-5-BF`, each with `instructions = pid_instructions`. The package ships `inst/extdata/pid5.json` with 220 items named `pid5_001` to `pid5_220`. `pid5sf.json` holds 100 named `pid5sf_001` to `pid5sf_100`, and `pid5bf.json` holds 25 named `pid5bf_01` to `pid5bf_25`. No file carries keying. Each has a byte-identical copy in `pkgdown/assets/downloads/` and a `json` row in `hitop_artifacts`, which grew from 41 to 44 rows. `test-json-export.R` locks all five stems through `spec_items()`, which subsets and orders the expected side as the writer does. It adds four `pid5sf` plants: a leaked full-form item, a dropped item, a swapped pair and a changed `maxItem`. One `pid5bf` padding plant sits beside them and the six `hitopbr` plants. Each PID-5 download article carries the JSON card. NEWS has an entry, and the `DESIGN.md` generator sentence names the PID-5.

**Decisions:** none cross-cutting. At implement, T2, T3 and T4 shared one commit. The download-page link lock reds the suite from the moment the manifest gains rows until the articles link them.
