# M103: One build at a time in the builder, with its settings fixed at the click

**Status:** done (2026-09-21, PR #113 https://github.com/jmgirard/hitop/pull/113; code in jmgirard/hitop-builder PR #18 https://github.com/jmgirard/hitop-builder/pull/18, merged as `840dace`)

**Goal:** A builder build runs alone, on the settings it started with, so each saved bundle holds only the files of that build.

**Outcome:** In hitop-builder `index.html`, a page-level `let building` flag sits beside `bootAbandoned`. `download()` returns at its first line while the flag is set. Inside its `try`, it sets the flag, disables `.downloads button` and writes the building status. It clears the flag first in `finally`. `refreshTally()` disables the button on `bootAbandoned || building || selected().length === 0`, so a tick, an untick or Select all during a build leaves it off. `download()` now reads paper size, the three `namingValue()` names and `el('required')` before its first `await`. The older reads (`selected()`, shuffle, numbering) were already there. `#downloadHint` now says the button is on while at least one scale is ticked and no build is running. `tests/smoke.spec.js` adds A8: after the Word click, the test ticks a second scale and reads `isDisabled()` and the tally once. `tests/plants.mjs` adds plant (i), which drops the flag from `refreshTally()` and fails A8 alone. Builder PR #17 (the M101 code) was merged first as `bd24032`. This repo: tracking only, plus a format-card candidate row.
