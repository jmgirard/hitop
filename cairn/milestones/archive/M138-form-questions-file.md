# M138: The hitop-form link builder reads the researcher's questions from a spreadsheet file and writes them back as one

**Status:** done (2026-09-28, PR #149 https://github.com/jmgirard/hitop/pull/149, merged 2026-09-28T22:57:27Z, with the companion jmgirard/hitop-form#17 merged 2026-09-28T22:27:26Z).

**Goal:** A researcher writes the questions of a study in a spreadsheet and saves it as a CSV file. The link builder loads that file and fills the question editor of M137 from it.

**Outcome:** In hitop-form, form.js gains `readQuestionsCsv()`, `writeQuestionsCsv()` and `QUESTION_COLUMNS`, and exports `saveFile()`. The reader decodes with a fatal UTF-8 decoder, refuses a decoded NUL as UTF-16, and parses RFC 4180 CSV with CR LF or LF. It trims each field after its quotes, skips blank rows, and passes the questions through `checkQuestions()`. A new `field` option there names the file's column, and its default messages are unchanged. A refusal of a whole-file fault names no row. A header fault names "row 1, field N" or the missing column. Any other fault names "row R, column X", or a field number past the last column. link.html gains "Load questions from a file", "Download these questions" (refused for an empty or faulty editor) and "Download a template". A saved file is UTF-8 with a byte-order mark and CR LF. The README gains "Write your questions in a spreadsheet", and the new spec `tests/link-questions-file.spec.js` brings the suite to 633 tests. In hitop, the online-collection article gains a paragraph, and NEWS an entry.

**Decisions:** M138-D1: trim every cell, and refuse a download of an empty or faulty editor. M138-D2 corrects M138-D1: a space outside a quoted cell's quotes is refused.
