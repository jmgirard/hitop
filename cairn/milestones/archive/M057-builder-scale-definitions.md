# M057: Each scale in the browser builder shows its clinician definition

**Status:** done (2026-08-27, PR #63 https://github.com/jmgirard/hitop/pull/63)

**Goal:** A visitor choosing scales in the browser module builder can read each scale's clinician-facing definition without leaving the picker, taking the text from the installed package rather than a copy kept in the page.

**Outcome:** `hitopsr_definitions` gains a `camelCase` column naming whatever each of its 93 rows defines (the subscale where there is one, else the scale), derived in `data-raw/hitopsr_info.R` with the one differing label ("Non-suicidal Self-injury"/`NSSI`) paired explicitly and three set-equality guards stopping the rebuild on any stem disagreement with `hitopsr_scales` or `hitopsr_subscales`. `available_scales()` returns a fourth column, `Brief`, via the internal `scale_definitions()`, which matches on that stem — never on a printed name — and aborts with class `hitop_missing_definition`, attributed to `available_scales()`, rather than returning a hole. `module_definition_tables()` is the sibling of `module_scale_tables()`, so an instrument with a scale table and no definitions is a missing key, not a column of `NA`. In [hitop-builder](https://github.com/jmgirard/hitop-builder) (PR #6, held open until r-universe rebuilds), each scale row carries a `.desc` popup wired by `aria-describedby`, shown on `pointerenter` after 300 ms and on checkbox focus, hidden on Escape with a dismissal flag; `definitionsAvailable()` gates the affordance all-or-nothing, so an older package renders the list as before.

**Decisions:** none cross-cutting. Milestone-local, at the gates: the stem keys all 93 definition rows; the rebuild stops on a stem-set disagreement; the hover target is the whole scale row rather than a per-row marker.
