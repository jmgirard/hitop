# M137: A study link can carry the researcher's own questions, which hitop-form asks before or after the form and writes as q_ columns

**Status:** done (2026-09-28, PR #148 https://github.com/jmgirard/hitop/pull/148, merged 2026-09-28T21:10:49Z, with the companion jmgirard/hitop-form#16 merged 2026-09-28T20:41:15Z)

**Goal:** A study link's `questions` field holds the researcher's own questions. The page asks them on a screen before the start screen or after the last item page. It writes each answer in a `q_<name>` column after the item columns.

**Outcome:** In hitop-form, `checkQuestions()` in `parseLink()` checks the `before` and `after` lists. A link holds up to 50 questions of four types: `text`, `number`, `choice` and `multi`. Each question can be `required`, and a `number` question can have `min` and `max`. Each fault is refused by name and position. The line-break set is Unicode's mandatory breaks. `runForm()` gains the "Before you begin" and "Before you finish" screens, with their checks and focus moves. A `number` input with a `min` of 0 or more asks for the numeric keypad, and any other asks for none. `questionColumns()` writes one `q_` column per question after the items in the file, the row and `storeSql()`. A choice is stored as its position from 1, and a multi as ascending positions joined by spaces. link.html gains a question editor with Move up, Move down and Remove. It writes questions as `?z=` and fills the editor from a `?z=` link. `encodeLink()` refuses a setup over the page's 100,000 bytes. The README gains "Ask your own questions", and four new Playwright specs bring the suite to 587 tests. In hitop, the work adds a page-saved fixture and reader test, the article section "Your own questions", and NEWS.
