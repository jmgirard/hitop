# M105: The builder's format cards look off while a build runs

**Status:** done (2026-09-21, PR #115 https://github.com/jmgirard/hitop/pull/115; code in jmgirard/hitop-builder PR #20 https://github.com/jmgirard/hitop-builder/pull/20, merged as `6ac767e`)

**Goal:** While a build runs, the builder's format cards look disabled but the current card keeps its check.

**Outcome:** In hitop-builder `index.html`, two `.formats button:disabled` rules come after the `aria-current` rules. They give every card the page's disabled pair, a dashed border and no shadow, and they set `.fmtname` and `.fmtwhat` to `--disabled-fg`. The `::after` and `::before` check rules are untouched, so the current card keeps its check. The rule comment says what each rule overrides. The current-card comment says that the disabled rule greys the fill during a build. README.md step 2 says that the cards look grey with a dashed border while a build runs. Its file table names the `PLANTS` list in place of a stale count. `tests/smoke.spec.js` adds A10, which waits for the card animations to end during the Word build. It compares each card's background, border colour and both text colours with the disabled `#downloadBtn`. It also asserts a dashed border, no shadow and a "Building" status. `tests/plants.mjs` adds plant (k), which removes both rules and fails A10 alone. This repo: tracking only, plus one candidate-row extension.

**Decisions:** none cross-cutting. Plan gate: grey all three cards and keep the check on the current card, and guard it with a smoke assertion plus a plant.

The PR conversation was empty. Blame-history and prior-review lenses: no finding. Diff-bug lens: no defect and 14 notes.
