# M152: Hosted setup files for study links

**Status:** done (2026-10-01, PR #161 https://github.com/jmgirard/hitop/pull/161; companion hitop-form PR #25 https://github.com/jmgirard/hitop-form/pull/25)

**Goal:** A researcher can keep a study's setup in a JSON file they host, and a short study link that names the file's address and fingerprint opens the online form with that setup, while a link that carries the whole setup stays the default.

**Outcome:** In hitop-form `form.js`, a link with `setup` (an absolute `https:` address) and `sha256` and neither `c` nor `z` runs `fetchSetup()`. It fetches with `cache: 'no-store'`, `credentials: 'omit'` and `referrerPolicy: 'no-referrer'`, reads at most 100,000 bytes, and aborts after `SETUP_TIMEOUT_MS` (30,000). It decodes UTF-8 with `fatal: true` and parses JSON. `setupFingerprint()` is the SHA-256 of `JSON.stringify` of the parsed value, base64url without padding. A match goes through the `c`/`z` checks. Each fault is named under "Details for the study team", a file too deep to write back out as fault `depth`. `checkParticipantParam()` refuses `setup` and `sha256`, and `saveFile()` takes a type. In `link.html`, the "Where the setup is kept" fieldset offers "In the study link" and "In a file I host". "Download the setup file" saves pretty-printed `setup.json`. "Make the link" fetches the address and requires a fingerprint match, and an opened `setup` link fills the form. A changed file gets "Fill in the form from the current file". `build()` reads the form through `readForm()`. The builder says that anyone can read a public setup file and see where responses go. Tests: `setupfile.spec.js`, `link-setupfile.spec.js`, N10, and S8, S9 and S12 extended (951 tests). The README section, the hitop article section and NEWS name the feature. Source note `cairn/references/github2026rawheaders.md` holds GitHub's raw-file headers.
