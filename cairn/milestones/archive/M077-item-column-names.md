# M077: The shipped HiTOP datasets, `rename_hitopsr_items()` and the `label_*()` family name item columns as the REDCap export does

**Status:** done (2026-09-01, PR #83 https://github.com/jmgirard/hitop/pull/83)

**Goal:** One item-column naming pattern for the HiTOP instruments — the one `generate_redcap_*()` already writes — so data collected through the package's own exports, the shipped example datasets, and the rename and label helpers agree, and a reader keeps one selection idiom across every HiTOP-SR and HiTOP-BR example.

**Outcome:** `ku_hitopsr` and `sim_hitopsr` item columns are `hsr_001`..`hsr_405`, `ku_hitopbr` and `sim_hitopbr` are `hbr_01`..`hbr_45`, renamed by `data-raw/rename_item_columns.R` from the objects at `7e06f40e` with values and column order asserted identical; `data-raw/sim_hitopsr.R`, `sim_hitopbr.R` and `ku_data.R` build the same names next run (`num_range()` selections replaced by `all_of()`). `item_names(prefix, n, max_n)` in `R/util.R` pastes `prefix` literally and pads to the width of `max_n`; `build_redcap_zip()`, `rename_hitopsr_items()` (both methods), `label_hitopsr()` and `label_hitopbr()` build names through it, the three helpers now padded for every `prefix` with defaults `"hsr_"` / `"hbr_"`, so `label_*(x, target = "scales")` matches `score_*()` output with no `prefix`. `label_*()` warn under the class `hitop_unpadded_items`, via `unpadded_item_cols()` and `warn_unpadded_items()`, naming prefixed columns whose number lacks the padding; a padded subset warns nothing. Vignettes, three articles, roxygen examples, tests and `data-raw/characterize_calc_se.R` moved to the new names; `test-data-item-names.R` pins the four datasets against the pattern written from the keying tables; NEWS Breaking-changes entry; `cairn/DESIGN.md` utilities line names the pattern. The Qualtrics export writes the same pattern with an uppercase stem (`HSR_001`), which the docs now say.
