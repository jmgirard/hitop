# M140: A study link can field two or more instruments in one hitop-form session

**Status:** done (2026-09-28, PR #151 https://github.com/jmgirard/hitop/pull/151, merged 2026-09-29T04:04:54Z). Companion: hitop-form PR #18 https://github.com/jmgirard/hitop-form/pull/18, merged 2026-09-29T03:45:57Z.

**Goal:** A study link's `instruments` field lists two or more instruments. The page gives them one after another in one session. It writes one row with a group of item columns per instrument, in the file shape that M139 reads.

**Outcome:** In hitop-form, `checkInstruments()` in `parseLink()` accepts 2 or 3 distinct known names. It refuses by name a list beside `instrument`, a value that is not a list, and a wrong count. It also refuses an entry that is not a known name (nested lists included), a repeated name and more than one PID-5 form. A `module` applies only to the HiTOP-SR entry. `fetchExports()` loads every export first. `runForm()` gives each instrument its own start screen ("Part n of N"), pages and answers. The row, the file, both sends and the builder's SQL hold one item group per instrument in link order. The `instrument` and `form_build` cells are space-joined, and a shuffle stays within each instrument (D-080). link.html has an ordered list of up to three instrument rows with the same checks and a `c`/`z` prefill. Tests: six new spec files, a list-link network walk and two SQL fixtures. In hitop: the saved fixture `responses-multi-page-shuffled.csv` with a reader-and-scoring test, the article section "Several instruments in one session" and NEWS.

**Decisions:** M140-D1 (implement gate): the builder's list editor of up to three rows, a file name of the stems joined by "-", and a "Part n of N" line on each start screen under a list link. The file shape is D-080.

**Review:** two passes, three-lens fan-out each. Pass 1 found 19 findings. F1 showed AC1 failing (a nested entry passed `checkInstruments()`), so it was defect return 1, and T9 to T12 fixed 13 findings. Pass 2 found 13 findings and no criterion failing. Fixed at the gate: an article `item_order` sentence wrong for a module in a list, a missing one-sheet-per-list-link rule, single-instrument wording and line wraps. Deferred to the `z` link gaps row: Move up/down on the end rows, the builder reload probed in Chromium only, and a late refusal of an array in `instrument` (as on main). Rejected: 6 low findings (design choices or weak). CI: hitop-form 1 of 1, hitop 8 of 8. No lesson added (LESSONS at its byte budget).
