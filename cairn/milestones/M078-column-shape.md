# M078: The per-scale tables the package ships or returns join on one column shape

- **Status:** review
- **Priority:** normal
- **Depends on:** —

- **Branch/PR:** `m078-column-shape` / https://github.com/jmgirard/hitop/pull/84

## Goal

A caller joining the package's per-scale tables to each other or to scored output — the shipped `*_scales`, `hitopsr_subscales` and `*_devstats` datasets, a `reliability_*()` return, `available_scales()` — meets one integer `nItems` and a `camelCase` stem column on every one of them, and the two devstats tables and the reliability return spell their display-name column `Scale` as `available_scales()` does, with no value moved.

## Scope

User-facing tier: the deliverable changes the storage type of a column in four documented datasets (six tibbles), renames a column in two, and adds a column to three exported functions' return value.

**In:** (a) `nItems` becomes integer in `hitopsr_scales`, `hitopsr_subscales`, `hitopbr_scales` and each element of `pid_scales`, by editing the builders (`data-raw/hitopsr_info.R:20,39`, `data-raw/hitopbr_info.R:36`, `data-raw/pid_info.R:20,35,50,75` — `purrr::map_dbl` → `map_int`, `as.numeric` → `as.integer`) and re-running them; every other column of every object those scripts save is identical to the object before the run. `available_scales()` drops the `as.integer()` coercion and its comment (`R/available_scales.R:50-53`). (b) `reliability_pid5()`, `reliability_hitopsr()` (full and `module` path) and `reliability_hitopbr()` return a `camelCase` column between `Scale` and `nItems`, read from the keying table's `camelCase` column on the same row `Scale` is read from (D-046's supplier pattern: `reliability_engine()` takes a `scale_stems` argument parallel to `scale_names`, guarded to the same length; `module_engine_inputs()` supplies it from `kept$camelCase`). (c) `hitopsr_devstats` and `hitopbr_devstats` rename their first column `scale` → `Scale`, by editing `data-raw/hitopsr_devstats.R` and `data-raw/hitopbr_devstats.R` and re-running them; `data-raw/verify_hitopsr_devstats.R` and `verify_hitopbr_devstats.R` read the new name. Roxygen (`R/data.R` `@format` blocks; the three `@return` blocks), `cairn/DESIGN.md:33,44`, tests, `cairn/LESSONS.md`'s M037 line, and NEWS follow. Both column changes take D-018's migration path — one release, no dual column, no shim — with the pre-1.0 deprecation cycle waived by Jeff at the 2026-09-01 plan gate (D-053, written with this plan). No scored, reliability, interval or devstats value moves; no keying content moves (IP1 sign-off for regenerating the four keying-table files given at the same gate).

**Out:** `p-Factor` capitalization → its own candidate row; PID-5 item-column naming → its candidate row; a `Scale` column on `pid_scales` (whose display column is `Facet` or `Domain` by version) → not planned, the reliability return is where the PID-5 gets a `Scale`; `interval_*()`, which match on `camelCase` and read no renamed column → untouched, their existing tests stand as the guard; the `hitop_module()` object, whose `nItems` is already integer → untouched; the M061 NEWS text in the 0.2.0 section saying the tables store a double → left as the record of that release, the new entry says what changed since.
